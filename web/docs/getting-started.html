Getting started

From a website address to an app you can install, in about ten minutes of your time plus the build itself.

Before you begin

Your website should already work on a phone. Open it on one and scroll around. If it is hard to use in a mobile browser it will be exactly as hard inside the app - the app shows your real site, so it inherits whatever the site does.

Create the app

  1. Press New app Give it a name and your website address. The name is what appears under the icon on the phone, so keep it short - long names get cut off by the launcher.
  2. Check the identifiers on the Identity page Web2App suggests an Android package name and an iOS bundle ID from your site's address, for example com.jokeb.mobile. Change them now if you want something else.
    These are permanent once you publish

    Google Play and the App Store both key a listing to its identifier. Changing it after release means a brand new listing, with none of your reviews, ratings or installs - not an update. Settle it before your first upload.

  3. Add your icon and splash screen on Branding A square PNG for the icon, at least 512 by 512. The splash is what fills the screen while the app starts.
  4. Set it up in Studio Your brand colour, which native modules to include, and whether you want a native bottom navigation bar. The phone preview shows your real website as you work.
  5. Upload a signing key on Signing Android will not accept an app that is not signed. If you have never made one, that page walks you through it.
  6. Press Build The log streams live. The first build of an app takes several minutes because it downloads the Android toolchain; later builds are faster. You can close the tab - the build carries on without you.
  7. Download and install Take the APK, put it on an Android phone, open it. Android will ask you to allow installing from this source; that is normal for an app that has not come from the Play Store yet.

What you get

FileWhat it is for
APK Install straight onto an Android phone. This is what you test with and what you send to people to try.
AAB The Android App Bundle. This is what Google Play accepts for publishing. You cannot install it on a phone directly.
Project .zip The complete Flutter project, for building the iPhone version on a Mac. See Publishing.
Changing your site needs no new build

The app loads your live website. Publish a change and every installed app shows it at once. You only need a new build when you change something about the app itself - the icon, the navigation, the modules, the name.

If the build fails

The build page puts a plain sentence above the raw log when it recognises the failure - a bad URL, a missing keystore, an Android licence that has not been accepted, or the machine running out of memory. When it does not recognise the failure it shows the log unchanged rather than guessing at a cause, so read the last twenty lines or so.
