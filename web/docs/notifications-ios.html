iPhone and APNs

Firebase delivers to iPhones through Apple's own push service, so there is one extra connection to make: Firebase has to be allowed to send on your behalf.

You can skip this entirely for now

None of it affects Android. If you are launching on Android first, leave this until you come to the iPhone version - your Android notifications work without any of it.

What you need

  • A paid Apple Developer account, in your own name.
  • A Mac, to build the iPhone app. Apple's tools do not run anywhere else.
  • A physical iPhone. Push notifications do not work in the simulator.

Add the iOS app to Firebase

  1. Add an iOS app to your existing project The same Firebase project as Android. Do not make a second one.
  2. Use the exact bundle ID Copy it from the Notifications page. It is usually the same string as your Android package name, but Firebase treats them as separate apps.
  3. Download GoogleService-Info.plist and upload it On the Notifications page. Web2App checks it against your bundle ID, the same way it checks the Android file.

Create the Apple push key

This is the credential that lets Firebase hand messages to Apple. One key works for all your apps and it does not expire.

  1. Open the Apple Developer site Go to Certificates, Identifiers & Profiles, then Keys.
  2. Create a key with Apple Push Notifications service enabled Give it a name you will recognise later.
  3. Download the .p8 file
    You can only download it once

    Apple will not let you download it again. Save it somewhere you will still have it in two years. If you lose it, you revoke it and make a new one.

  4. Note the Key ID and your Team ID The Key ID is shown next to the key. The Team ID is in the top right of the developer site, and in Membership.
  5. Upload it to Firebase In your Firebase project: Project settings → Cloud Messaging → your iOS app → APNs Authentication Key. Upload the .p8 and enter the Key ID and Team ID.
The key goes to Firebase, not to us

Web2App never asks for the .p8, never stores it and has no use for it. It is a credential that can send notifications to your users, and the fewer places it exists the better. Upload it straight to Firebase.

On the Mac

Download the project .zip from the Build page and open the ios folder in Xcode. Two things to do there:

  1. Add the Push Notifications capability Select the Runner target, open Signing & Capabilities, press + Capability and add Push Notifications. This is one checkbox, and it is the only part of iOS setup that has to happen in Xcode rather than here.
    Why this is not done for you

    It is recorded in Xcode's own project file, in a format with no public specification. Editing that from a server is the kind of change that works until Apple alters the format and then fails on your Mac, where we cannot see it. One checkbox, done by the person who already has Xcode open, is the more reliable answer.

  2. Set your signing team Same screen. Xcode handles the certificates from there.
  3. Build to a real iPhone and test Send yourself a message from Firebase's composer. Notifications do not work in the simulator, so this has to be a physical device.

If nothing arrives on iPhone

  • Is the Push Notifications capability actually added in Xcode?
  • Is the APNs key uploaded in Firebase, against the right iOS app?
  • Is the bundle ID in Xcode identical to the one in Firebase?
  • Are you testing on a real device rather than the simulator?
  • Did you accept the permission prompt?

Android and iPhone fail independently here. Android arriving tells you the Firebase project and your sending code are right, which usually narrows an iPhone problem down to the APNs key or the Xcode capability.
